로그인한 뒤 앱의 **Evals**(`/evals`)에서 검증할 대상을 골라요. 세 탭은 서로 다른 것을 실행해요.

| 탭 | 실제로 실행하는 대상 | 준비할 것 |
| --- | --- | --- |
| **프롬프트 모델 평가** | 작성한 시스템 프롬프트와 사용자 턴을 선택한 모델에 직접 보내요. Agent 그래프·Live 배포본은 실행하지 않아요. | 사용 가능한 OpenAI 또는 OpenRouter 모델과 제공자 키 |
| **배포 에이전트 실시간 테스트** | Agent의 **현재 운영 Live 버전**으로 새 텍스트 대화를 만들어요. | Agent의 활성 운영 배포본 |
| **대화 시뮬레이터** | 가상 사용자와 선택한 대상 모델이 텍스트로 대화해요. Agent 그래프·Live 배포본은 실행하지 않아요. | 사용 가능한 대상 모델과 플랫폼 테스터·채점 모델 |

## 모델 평가

1. **프롬프트 모델 평가 → 새 평가**에서 이름, 대상 제공자와 모델 ID, 시스템 프롬프트를 입력해요. `{{product_name}}` 같은 변수도 추가할 수 있어요.
2. **사용자 턴** 뒤에 **예상 응답**을 놓아요. 기대하는 도구 호출이 있다면 같은 사용자 턴 뒤에 **도구 Mock**의 이름·반환 결과와 선택적인 기대 JSON 인자를 호출 순서대로 작성해요. Mock은 다음 사용자 턴으로 넘어가지 않아요.
3. **저장 → 평가 실행**을 눌러요. 실행 기록에서 실제 답변, GPT-6-Luna의 의미 판정과 이유, 도구 호출·인자 검증을 확인해요.

작성한 Mock은 모두 정해진 순서로 호출되어야 해요. 기대 인자를 지정하면 실제 인자의 구조와 값을 정확히 비교해요. 호출이 빠지거나 인자가 다르면 실패하고, 예상하지 않은 도구 호출은 오류예요. 실제 외부 도구는 실행하지 않아요. 이전 실행은 새 채점 방식과 다를 수 있어요.

<Note>
저장 후 실행해야 하고 예상 응답이 하나 이상 필요해요. 평가 정의는 계정당 최대 100개, 변수는 16개, 사용자 턴과 도구 턴은 각각 최대 12개(전체 최대 24개)예요. 실행 이력은 최근 100개까지 조회해요. 대상 모델과 플랫폼 채점 모델을 호출하며 비용이 발생할 수 있어요.
</Note>

## 대화 시뮬레이션

**대화 시뮬레이터 → 새 시나리오**에서 대상 모델과 시스템 프롬프트, 가상 사용자 프롬프트, 1~6턴과 1~8개 성공 기준을 입력해요. 필요하면 도구 Mock을 최대 12개까지 추가해요. 저장 후 실행하면 선택한 모델이 응답하고 플랫폼 `gpt-6-luna`가 가상 사용자와 기준별 채점을 담당해요.

Mock은 전체 대화에서 작성한 순서로 호출되어야 해요. 호출 여부와 기대 인자는 코드로 검증하고, 실제 API·MCP 도구는 호출하지 않아요. 결과에서 전체 대화, 기준별 이유, 도구 검증과 실행 당시 설정을 확인해요.

## Live 테스트

1. **배포 에이전트 실시간 테스트** 탭에서 Agent를 선택하고 표시된 **배포 버전 vN**과 읽기 전용 시스템 프롬프트를 확인해요.
2. **테스트 시작**을 누르고 필요한 변수를 입력해 대화해요. 대화 내용과 실행 기록·성능을 확인해요. 새 대화가 만들어지고 사용량이 발생할 수 있어요.

이 탭은 [Agent 편집기의 초안이나 테스트 revision](/ai/agents)이 아니라 **현재 Live**만 사용해요. **테스트 시작**이 비활성이면 해당 Agent의 운영 배포본이 없는지 확인하고 편집기에서 **Deploy**해요. 모델 평가가 오류로 끝나면 제공자 키·모델 ID(OpenRouter는 활성 요금 등록도 필요해요)와 Mock 호출 순서를 확인해요. 실패로 채점됐다면 실제 답변과 예상 응답을 비교해요. Live 대화는 텍스트 테스트이므로 사람 상담원으로의 SIP 전화 연결을 검증하지 않아요.

## API와 Claude 연동

[자원 관리 API 키](/developers/keys)에 `evals:read`, `evals:write`, `simulations:read`, `simulations:write` 중 필요한 권한을 부여해요. 삭제에는 각 자원의 `:delete` 권한이 필요해요. 키는 `Authorization: Bearer <관리 키>`로 보내고 비밀 저장소에 보관해요.

평가와 시뮬레이션은 각각 `/api/v1/evals`, `/api/v1/simulations`에서 생성·조회·수정·삭제해요. `POST /api/v1/evals/{id}/runs` 또는 `POST /api/v1/simulations/{id}/runs`는 완료 결과를 반환하고, 같은 경로의 `GET`은 실행 이력을 반환해요. 응답이 유실되면 이력을 확인한 뒤 다시 실행하세요. 재요청은 새 실행과 추가 모델 비용을 만들 수 있어요.

`ownyai` CLI의 기본 HTTP 제한은 30초라 모델 실행보다 짧을 수 있어요. 실행 명령에는 예를 들어 `--timeout 60`을 지정하고, 응답이 없으면 재시도 전에 이력을 확인해요.

```json
{
  "name": "주문 상태",
  "provider": "openai",
  "model": "gpt-6-sol",
  "systemPrompt": "주문 상태를 확인해 안내하세요.",
  "turns": [
    { "id": "user-1", "role": "user", "content": "주문 42의 상태는?" },
    { "id": "tool-1", "role": "tool", "toolName": "lookup_order", "content": "{\"status\":\"배송 중\"}", "expectedArguments": { "orderId": 42 } },
    { "id": "expected-1", "role": "assistant", "content": "주문이 배송 중이라고 안내한다." }
  ],
  "variables": {}
}
```

위 객체를 평가 생성 요청의 JSON 본문으로 사용해요. MCP 어댑터가 배포·설정된 환경에서는 같은 관리 키로 Claude 등에 연결하고 `list_evaluations`, `run_evaluation`, `judge_evaluation`, `list_simulations`, `run_simulation` 등을 사용할 수 있어요. 기존 전화용 키와 관리 키는 서로 다른 권한이에요.

### 외부 모델 기록 채점

Claude 등에서 이미 실행한 결과는 `POST /api/v1/evals/{id}/runs/judge`에 보내요. 저장된 평가의 각 사용자 턴에 대응하는 `steps`를 같은 순서로 하나씩 제출하고, 호출이 없으면 `tools`에 빈 배열을 넣어요.

```json
{
  "steps": [
    {
      "userTurnId": "user-1",
      "actual": "주문 42가 배송 중입니다.",
      "tools": [
        { "name": "lookup_order", "args": { "orderId": 42 }, "result": "{\"status\":\"배송 중\"}" }
      ]
    }
  ]
}
```

이 경로는 대상 모델을 다시 호출하지 않고 플랫폼 `gpt-6-luna`로 채점해 기존 실행 이력에 저장해요. 도구 인자와 결과는 **호출자가 제출한 증거**일 뿐 실제 도구 실행을 보증하지 않아요. 기록에 키나 비밀을 넣지 마세요.
