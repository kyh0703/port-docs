---
title: "모델 시나리오와 Live Agent 평가하기"
description: "독립적인 프롬프트 모델 평가를 실행하고 현재 운영 배포본을 텍스트로 확인해요"
---

로그인한 뒤 앱의 **Evals**(`/evals`)에서 검증하려는 대상을 먼저 골라요. 두 탭은 서로 다른 것을 실행해요.

| 탭 | 실제로 실행하는 대상 | 준비할 것 |
| --- | --- | --- |
| **프롬프트 모델 평가** | 작성한 시스템 프롬프트와 사용자 턴을 선택한 모델에 직접 보내요. Agent 그래프·Live 배포본은 실행하지 않아요. | 사용 가능한 OpenAI 또는 OpenRouter 모델과 제공자 키 |
| **배포 에이전트 실시간 테스트** | Agent의 **현재 운영 Live 버전**으로 새 텍스트 대화를 만들어요. | Agent의 활성 운영 배포본 |

## 저장한 시나리오로 모델을 평가해요

1. **프롬프트 모델 평가 → 새 평가**에서 이름, OpenAI/OpenRouter 제공자, 모델 ID와 시스템 프롬프트를 입력해요. 필요하면 `{{product_name}}` 같은 변수 이름과 값을 추가해 프롬프트·턴에 사용해요.
2. **사용자 턴** 뒤에 **예상 응답**을 배치해요. 도구 호출을 검증하려면 해당 사용자 턴 뒤에 **도구 Mock**의 이름과 돌려줄 결과를 순서대로 작성해요. 다음 사용자 턴으로 넘어가면 이전 Mock은 쓰지 않아요.
3. **저장 → 평가 실행**을 눌러요. **실행 기록**에서 통과·실패·오류와 점수, 실제 답변·예상 답변·Mock 도구 호출을 확인해요. 기록에는 실행 당시의 설정도 남아요.

예상 응답은 대소문자와 공백을 정규화한 **실제 답변 안에 포함**되면 통과해요. 문장 전체 일치 검사가 아니에요. Mock은 작성한 순서와 이름대로만 반환하며 실제 외부 도구를 호출하지 않아요. 모델이 다른 도구를 호출하면 오류가 날 수 있어요.

<Note>
저장 후 실행해야 하고, 사용자 턴 다음에 예상 응답이 하나 이상 필요해요. 평가 정의는 계정당 최대 100개, 변수는 16개, 사용자 턴과 도구 턴은 각각 최대 12개(전체 턴은 최대 24개)예요. 실행 기록은 평가마다 최근 100개까지 조회하며, 같은 사용자가 동시에 실행할 수 있는 평가는 1개예요. 모델 API 호출에 비용이 발생할 수 있어요.
</Note>

## 현재 Live Agent를 텍스트로 확인해요

1. **배포 에이전트 실시간 테스트** 탭에서 Agent를 선택하고 표시된 **배포 버전 vN**과 읽기 전용 시스템 프롬프트를 확인해요.
2. **테스트 시작**을 누르고 필요한 변수를 입력해 대화해요. 대화 내용과 실행 기록·성능을 확인해요. 새 대화가 만들어지고 사용량이 발생할 수 있어요.

이 탭은 [Agent 편집기의 초안이나 테스트 revision](/ai/agents)이 아니라 **현재 Live**만 사용해요. **테스트 시작**이 비활성이면 해당 Agent의 운영 배포본이 없는지 확인하고 편집기에서 **Deploy**해요. 모델 평가가 오류로 끝나면 제공자 키·모델 ID(OpenRouter는 활성 요금 등록도 필요해요)와 Mock 호출 순서를 확인해요. 실패로 채점됐다면 실제 답변과 예상 응답을 비교해요. Live 대화는 텍스트 테스트이므로 사람 상담원으로의 SIP 전화 연결을 검증하지 않아요.
