---
title: "Evaluations"
description: "Run an independent prompt/model evaluation, then text-test the current production Agent"
---

Sign in and open **Evals** (`/evals`) in the app. Choose the target you want to check: the two tabs run different things.

| Tab | What it runs | Prerequisite |
| --- | --- | --- |
| **Prompt/model evaluation** | Sends your system prompt and user turns directly to the selected model. It does not run the Agent graph or Live deployment. | A usable OpenAI or OpenRouter model and provider credential |
| **Live deployed Agent test** | Creates a new text conversation using the Agent's **current production Live revision**. | An active production deployment for that Agent |

## Model scenarios

1. Under **Prompt/model evaluation → New evaluation**, enter a name, OpenAI/OpenRouter provider, model ID, and system prompt. If needed, add names and values for variables such as `{{product_name}}` to use in the prompt or turns.
2. Place an **Expected response** after a **User turn**. To check tool behavior, add **Tool mocks** after that user turn, in the expected call order, with each tool name and returned content. Mocks from one user turn do not carry over to the next.
3. Select **Save → Run evaluation**. In **Run history**, check pass/fail/error, score, actual and expected answers, and any mock tool calls. The record also retains the settings used for the run.

An expected response passes when it is **contained in the actual answer** after whitespace and case normalization; this is not an exact-answer check. Mocks return only the authored names and results in order. No real external tools run. A different tool call from the model can produce an error.

<Note>
Save before running; at least one expected response must follow a user turn. An account can have up to 100 evaluation definitions and 16 variables per definition. You can add up to 12 user turns and 12 tool turns (24 turns in total). Up to 100 recent runs are listed per evaluation, and only one evaluation can run at a time per user. Model API calls may incur costs.
</Note>

## Live Agent tests

1. Open the **Live deployed Agent test** tab, choose an Agent, and check the displayed **deployment revision vN** and read-only system prompts.
2. Select **Start test**, enter any required variables, and have a conversation. Check the transcript and execution/performance records. This creates a new conversation and may consume usage.

This tab runs **current Live**, not the [draft or test-only revision in the Agent editor](/en/ai/agents). If **Start test** is disabled, check whether the Agent has a production deployment and use **Deploy** in its editor. If the model evaluation errors, check the provider credential and model ID (OpenRouter also needs an active model price), then the mock call order. If it is graded as failed, compare the actual and expected answers. This Live conversation is a text test; it does not validate SIP phone transfer to a human.
