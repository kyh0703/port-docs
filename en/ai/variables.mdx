To insert a date, customer detail, or earlier tool result, use `{{name}}` in an [Agent's](/en/ai/agents) **system prompt** or **greeting**. After signing in, search and copy built-in tokens from **Variables**.

## System variables

| Tokens | Value and availability |
| --- | --- |
| `{{date}}`, `{{time}}`, `{{weekday}}`, `{{now}}` | Date, time, and weekday in Korea Standard Time (KST). Date tokens accept offsets up to ±366 days, for example `{{date+1}}`. |
| `{{year}}`, `{{month}}`, `{{day}}`, `{{calendar}}` | Year, month, day, and a Korean-language calendar covering 14 days from today. Year, month, and day values include Korean units. Put the calendar in the system prompt; in a greeting, all its dates may be read aloud. |
| `{{customer.number}}`, `{{call.direction}}` | Customer number is **phone-only** and empty on web chat. Call direction is formatted in Korean as `인바운드` or `아웃바운드`. |

## User variables

Add a new name such as `{{order_id}}` to a prompt or greeting; it becomes a user variable. Before an Agent test or outbound call, enter its value in the **Conversation variables** dialog and choose string, number, or boolean. If a saved value for that phone customer is prefilled in an outbound call, you can change it for this call. Check or edit saved values under **Customers > customer details > Customer attributes**. To reuse stored values in later conversations or extract values after a conversation, enable **Customer memory** for that Agent. A value supplied for this conversation takes precedence over a stored value with the same name.

## REST response bindings

Add an **output JSON Schema** to a [REST tool](/en/ai/tools). Scalar string, number, and boolean fields then become candidates named `api.<functionName>.<field>`. In the Agent node, open the receiving REST tool's **value sources** (double-arrow icon) and bind its **request argument** or `{{variable}}` in the URL to the earlier tool's response variable. The earlier tool must run and return a value first. Handoff parameters can also be selected as sources on reachable downstream nodes.

**Deploy** the Agent and check a new conversation for the substituted value. If it is missing, fill the required conversation input and check the tool URL binding. User variables are limited to **50 entries**, **64 UTF-8 bytes** per name, and **1,000 UTF-8 bytes** per string value. Names start with a lowercase English letter and use lowercase English letters, digits, and the separators `.`, `_`, or `-` between letters or digits. Values may contain Korean text. System names and reserved namespaces such as `api.` cannot be used for user variables.
