Choose a key based on **who sends the request**. After signing in, create and revoke keys under **API Keys**.

| Used by | Key | Scope | Storage |
| --- | --- | --- | --- |
| Your server | Private `ot_sk_` | Outbound HTTP calling API, MCP and A2A authentication | Server secret store |
| Existing server integrations | `ot_call_` / `ot_mcp_` | Outbound HTTP calls / MCP and A2A authentication only, respectively | Server secret store |
| Evaluation automation | Management `ot_sk_mgmt_` | Selected resource `read`, `write`, and `delete` scopes | Server secret store |
| Your website | Public `ot_pk_` | Browser sessions for specified web chat endpoints and Origins | Web chat installation code |

<Note>
A key's authentication scope does not guarantee that a runtime feature is enabled. **MCP calling tools are disabled in the current deployment**; use the [Outbound API](/en/developers/calls) for server calls. External A2A task execution is not supported either.
</Note>

## Resource management keys

Under **API Keys → Resource management API keys**, select only the scopes you need: `evals:read`, `evals:write`, `evals:delete`, `simulations:read`, `simulations:write`, or `simulations:delete`. Running a scenario requires its resource's `:write` scope; wildcard scopes are not supported. The full key is shown only once.

Management keys are separate from Private calling keys. MCP evaluation tools require an adapter that supports management keys; this does not grant telephone access. If the key has an IP allowlist, client-IP attestation must be configured between the MCP adapter and API.

## Private keys

In **API Keys → Private API Keys**, select **Issue token**. The full key is visible only immediately after issuance; put it in your server's secret store. Send it as `Authorization: Bearer <Private key>`. An existing `ot_mcp_` key cannot initiate calls. A Public key cannot authenticate outbound calls or MCP.

If a key is compromised, **rotate** or **revoke** it. Do not assume that the old key still works after rotation. Update the value on your server, then check [call requirements](/en/developers/calls) with the new key. Never place a Private key in browser code, public repositories, or an HTML embed.

## Public keys

1. Your account must already have a web chat endpoint. The channel-management screen and endpoint creation/configuration APIs are no longer available.
2. Under **API Keys → Public API Keys**, select a name, allowed Origins, and the existing endpoints that this key may access. An Origin is the scheme and host, plus port when applicable, for example `https://example.com`. A key cannot be issued without an eligible endpoint.
3. Use the existing endpoint's public ID and the new Public key in the installation code. See [Existing web chat setup](/en/developers/web-chat) for a verification checklist.

Revoking the key blocks new sessions using it. If you change the key, check both the existing endpoint and the key's allowed Origins, then update the installation code. Public keys are not secrets; still restrict them to the minimum necessary endpoints and Origins.
