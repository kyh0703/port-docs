Follow **create an Agent → publish to Live → check a new conversation**. Saving a draft does not publish it. Republish changes before expecting them to appear in new conversations.

## Agents

After signing in, create an Agent under **Agents**. Define what it handles, its greeting and response instructions, and the [knowledge](/en/ai/knowledge) or [tools](/en/ai/tools) it needs. Use **Deploy** to publish the first Live version. You can then run a text test in the editor. A later test revision is not Live; deploy again to make edits available to customer channels.

See [Agents](/en/ai/agents) for the detailed flow.

## Connections

The separate **Channels** screen and user APIs for connecting phone numbers or creating web chat endpoints are no longer available. App authentication, conversation connections, and existing phone and web chat connections remain supported.

Check the production revision with a [Live test](/en/ai/evaluations). For server calls through an existing number, see [Overview](/en/developers/). Use [Web chat setup](/en/developers/web-chat) only when an endpoint already exists.

## Conversation checks

Start a new conversation in the app or a Live test and ask a question. For an existing phone connection, use [Monitoring](/en/operations/monitoring) to inspect the connection and transcript. After a conversation ends, review [Conversations and customers](/en/operations/conversations). Publishing an Agent or accepting a call request does not by itself mean a customer was connected.

<Note>
Voice configuration changes do not alter calls already in progress. Check Agent edits and voice settings with a **new** conversation.
</Note>
