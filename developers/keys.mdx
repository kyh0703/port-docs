외부에서 Overthinker를 사용할 때는 **누가 요청을 보내는지**에 따라 키가 달라요. 로그인한 뒤 **API 키** 화면에서 발급·폐기할 수 있어요.

| 사용할 곳 | 키 | 허용 범위 | 보관 위치 |
| --- | --- | --- | --- |
| 내 서버 | Private `ot_sk_` | 발신 HTTP API, MCP·A2A 인증 | 서버의 비밀 저장소 |
| 기존 서버 연동 | `ot_call_` / `ot_mcp_` | 각각 발신 HTTP API / MCP·A2A 인증 전용 | 서버의 비밀 저장소 |
| 내 웹사이트 | Public `ot_pk_` | 지정한 웹챗과 허용 Origin에서 시작하는 브라우저 세션 | 웹챗 설치 코드 |

<Note>
키의 인증 범위와 실제로 열려 있는 기능은 달라요. 현재 운영 환경에서 **MCP 전화 도구는 활성화되지 않았어요**. 서버 발신은 [HTTP 통화 API](/developers/calls)를 사용해요. 외부 A2A 작업 실행도 지원하지 않아요.
</Note>

## 서버에서 통화를 시작할 때

**API 키 → Private API 키 → 토큰 발급**을 선택해요. 키 값은 발급 직후 한 번만 표시되므로 그 자리에서 서버의 비밀 저장소에 넣어요. 요청에는 `Authorization: Bearer <Private 키>`를 사용해요. 기존 `ot_mcp_` 키는 발신에 사용할 수 없고 Public 키는 서버 발신·MCP 인증에 사용할 수 없어요.

키가 유출됐다면 **재발급** 또는 **폐기**해요. 재발급으로 이전 키를 계속 사용할 수 있다고 가정하지 말고, 서버에 새 값을 반영한 뒤 [발신 조건 조회](/developers/calls)로 확인해요. 브라우저 코드, 공개 저장소, HTML 설치 코드에 Private 키를 넣지 마세요.

## 웹사이트에 웹챗을 넣을 때

1. 먼저 **채널 관리 → 웹챗**에서 Live Agent, 허용할 사이트 Origin과 사용 가능한 음성 프로필을 선택해 웹챗을 만들어요. 프로필은 현재 텍스트 웹챗에 적용되지 않아요.
2. **API 키 → Public API 키**에서 이름, 허용 Origin, 접근 가능한 웹챗을 선택해 발급해요. Origin은 `https://example.com`처럼 프로토콜·호스트·필요하면 포트를 포함한 정확한 값이에요.
3. **채널 관리 → 웹챗**에서 설치 코드를 복사해 같은 Origin의 사이트에 넣어요. [웹챗 설치 가이드](/developers/web-chat)에 확인 방법이 있어요.

키를 폐기하면 그 키로 새 웹챗 세션을 시작할 수 없어요. 키 또는 사이트 Origin을 변경했다면 채널·키의 허용 범위를 다시 확인하고 설치 코드를 새로 복사해요. Public 키는 비밀키가 아니지만 접근 가능한 웹챗과 Origin을 최소한으로 지정해요.
