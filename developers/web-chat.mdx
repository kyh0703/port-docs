---
title: "웹챗 설치"
description: "허용 Origin과 Public 키를 설정하고 채널의 설치 코드를 웹사이트에 넣어요"
---

웹챗은 고객이 접속한 페이지에서 실행돼요. 서버 발신에 사용하는 Private 키를 설치 코드에 넣지 말고, **웹챗 전용 Public API 키**를 사용해요.

## 준비

1. Overthinker에서 Agent를 **Live로 배포**해요.
2. **채널 → 웹챗**에서 웹챗을 만들어요. 연결할 Agent, 웹사이트의 허용 Origin과 사용 가능한 음성 프로필을 선택하고 활성 상태인지 확인해요. 음성 프로필은 현재 텍스트 웹챗의 소리를 바꾸지 않아요.
3. **API 키 → Public API 키**에서 해당 웹챗과 Origin을 허용하는 키를 만들어요. 기존 키가 이 웹챗과 Origin을 허용한다면 그대로 쓸 수 있어요.
4. 다시 **채널 → 웹챗**에서 해당 웹챗의 **설치 코드**를 복사해요. 사용할 수 있는 Public 키가 없으면 설치 코드 대신 키 발급 안내가 표시돼요.

Origin에는 사이트의 프로토콜, 도메인, 포트가 포함돼요. 예를 들어 `https://example.com`과 `https://www.example.com`은 달라요. 실제로 웹챗을 넣을 페이지의 Origin을 설정해요. Agent가 배포되지 않았거나 Origin이 일치하지 않으면 대화를 시작할 수 없어요.

## 설치 코드

채널 화면에서 복사한 스크립트를 사이트의 HTML에 추가해요. 실제 설치 코드는 다음 구조예요. 주소·웹챗 ID·공개 키를 임의로 만들지 말고 **화면에서 발급된 값**을 사용해요.

```html
<script src="<Overthinker 접속 주소>/web-chat/loader.js"
        data-endpoint="<웹챗 공개 ID>"
        data-public-key="<Public API 키>"
        async></script>
```

방문자가 허용된 Origin에서 페이지를 열면 로더가 웹챗 창을 표시하고 대화 세션을 시작해요. 브라우저의 공개 키는 비밀이 아니지만, 키가 허용하는 Origin과 웹챗은 서버에서도 검사해요. Private 키는 브라우저에 보내지 않아요.

## 문제 해결

- **설치 코드가 없어요:** 해당 웹챗과 Origin을 허용하는 활성 Public 키가 있는지 확인해요.
- **403:** 페이지의 실제 Origin과 채널·키에 설정한 Origin이 일치하는지, 키가 해당 웹챗에 허용됐는지 확인해요.
- **404:** 웹챗이 활성 상태인지, 연결한 Agent에 Live 배포본이 있는지 확인해요.
- **429:** 웹챗 시작 요청 제한에 걸렸어요. 새로고침을 반복하지 말고 잠시 뒤 다시 확인해요.

웹챗에서 시작한 대화는 텍스트 대화예요. 채널의 음성 프로필 선택은 이 텍스트 대화의 목소리를 바꾸지 않아요. 사이트의 Origin을 바꾸거나 새 키를 발급했다면 채널과 키의 허용 범위를 확인하고 새 설치 코드를 복사해요.
