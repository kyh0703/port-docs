---
title: "서버에서 발신 통화 만들기"
description: "Private 키로 통화를 만들고 Idempotency-Key와 callId로 결과를 확인해요"
---

발신 API는 서버에서 호출해요. [Private 키](/developers/)를 `Authorization: Bearer` 헤더에 보내고, 발신할 전화번호에 **Live 배포된 Agent**가 연결돼 있어야 해요. `agentId`와 `fromNumberId`는 해당 계정의 UUIDv7 ID예요. 번호가 연결되지 않았거나 통화 시간이 부족하면 시작할 수 없어요.

## 필요한 변수를 먼저 확인해요

`GET /api/v1/calls/requirements?agentId=<Agent UUIDv7>&fromNumberId=<전화번호 UUIDv7>`을 호출해요. 응답의 `data.variableNames`에는 이 Agent가 요구하는 변수 이름이 들어 있어요. `data.publishedId`와 `revision`도 현재 연결된 배포본을 알려줘요. 필요한 변수가 있다면 발신 요청의 `variables`에 빠짐없이 넣어요.

이 경로와 아래 요청에는 같은 Private 키를 `Authorization: Bearer <키>` 형식으로 보내요. 성공 응답은 `statusCode`, `message`, `data`로 감싸져 있어요.

## 통화를 만들어요

새 발신 시도마다 고유한 `Idempotency-Key`를 만들어요. 같은 시도를 재전송할 때는 **같은 키와 같은 본문**을 사용해요. 예시의 ID, 전화번호와 키는 실제 계정 값으로 바꿔야 해요.

```http
POST /api/v1/calls
Authorization: Bearer <Private 키>
Content-Type: application/json
Idempotency-Key: <이 시도에만 사용하는 고유 키>

{
  "agentId": "<Agent UUIDv7>",
  "fromNumberId": "<연결된 전화번호 UUIDv7>",
  "to": "+821012345678",
  "variables": {
    "고객명": "홍길동"
  }
}
```

`to`는 `+`로 시작하는 국제 전화번호(E.164)예요. `variables`는 Agent가 요구하지 않으면 생략할 수 있어요. 문자열·숫자·불리언만 넣을 수 있고, 최대 50개예요. 본문에 `publishedId`, `message` 같은 추가 필드를 넣으면 요청이 거부돼요.

성공하면 **201 Created**로 `data.callId`, `data.conversationId`, `data.status`를 돌려줘요. 상태는 `pending`, `uncertain`, `active`, `ended`, `failed` 중 하나예요. 응답을 받았어도 상대방이 통화를 받았다는 뜻은 아니에요.

## 결과를 확인해요

`GET /api/v1/calls/<callId>`를 같은 계정의 Private 키로 호출해요. 성공하면 **200**과 같은 형태의 `data`를 받아요. `uncertain`은 발신 결과가 확정되지 않은 상태예요. 이때 새 키로 다시 만들면 중복 발신할 수 있으니 기존 `callId`를 조회하거나 **원래 키와 원래 본문**으로 다시 요청해요.

- **400**: ID·전화번호·변수가 잘못됐거나 Idempotency-Key가 없어요. 필수 변수 누락 시 오류 상세에 누락된 이름이 포함돼요.
- **401/403**: 키가 유효하지 않거나 통화 권한이 없어요. MCP·A2A 전용 키로는 발신할 수 없어요.
- **404**: 계정 소유가 아닌 번호·통화거나, 번호에 Agent의 Live 배포본이 연결되지 않았어요.
- **409**: 다른 본문으로 키를 재사용했거나, 통화 시간·동시 통화 등 시작 조건이 충돌해요.
- **503**: 발신에 필요한 전화·음성 실행 환경을 사용할 수 없어요.

오류 응답은 `statusCode`, `message`, `error`, `data`를 포함해요. 인증 헤더가 있으면 잘못된 키를 브라우저 로그인 쿠키로 대신 인증하지 않아요.
